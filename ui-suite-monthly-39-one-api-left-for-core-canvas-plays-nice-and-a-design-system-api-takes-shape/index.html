Our 39th monthly UI Suite meeting (October 29, 2026) kept the 30-minute format, with 14 people in the room. The official part wrapped on time; nobody left, and the demos and questions ran another half hour. Some of the best material came from that second half.

Overall Summary

This month was about convergence. The Design Tokens API has landed, leaving one API to ship to core — style utilities and component mode, targeting Drupal 12.1. Display Builder shipped Beta 8 and Beta 9 and is 40 tickets from RC1. And Canvas, Display Builder and UI Patterns now work on the same site, side by side and together.

Mikael finally gave the CKEditor 5 demo and showed how UI Patterns can render a whole view as a component. Pierre connected our JSON Schema work to Dries' Rosetta initiative. And Shibin Das presented a Design System API concept that turned out to overlap heavily with the Style API headed for core.

Quick highlights:

  • Design Tokens API landed; one core API left, targeting 12.1.
  • Display Builder Beta 8 & 9 out; 40 easy, welcoming tickets to RC1.
  • Canvas compatibility: done.
  • UI Patterns: performance fix, CKEditor 5 submodule, Views display plugin.
  • UI Suite is now an official organization on drupal.org.
  • Next meeting: December 10.

Key Topics Discussed

Core: one API to go, and a ticket worth your opinion

With tokens in — "as important as SDC and the Icon API", per Pierre — the remaining scope is the Style API (12.1), an icon form element and schema references.

Pierre also flagged a core issue that deserves community input: with components, tokens and icons, more YAML discovery is moving into themes, which makes sites dependent on theme-provided plugins and themes less swappable. Pierre sees it as the price of the direction we've chosen; others want to mitigate or challenge it. Say so in the issue.

He also noted the display-building landscape is growing — Display Builder, Acquia's Canvas, newcomers, and FlowDrop by Shibin Das with an AI-first builder and a props editing panel. "The design system APIs are making a new ecosystem bloom." Friendly competition welcome.

Display Builder — Beta 8, Beta 9, 40 tickets to RC1

  • Beta 8 — symmetric translation, navigation top bar, buildable presets.
  • Beta 9 — the builder now renders in the admin theme (everything but the preview): more stability across themes, less custom code. Preview is a mode of the builder; page layouts get a homepage.

Beta 9 may be the last beta. RC1 is 40 tickets away — "no new features, only easy little tasks we need to do together." Welcoming tickets are available; now is the moment to join.

Two more items: Shibin Das built a Display Builder × Webform integration (Webform plugins as a source, live preview, the published result is your form layout) — demo hoped for next month. And Canvas compatibility is done: Pierre ran Canvas, Display Builder and UI Patterns on one site, with a Display Builder page layout containing Canvas content. Canvas never merged our upstream proposals, so Mikael and the team did all the work on our side.

UI Patterns — performance, CKEditor 5, Views

Releases 2.0.22 and 2.0.23 landed in October. The headline: the long-awaited performance fix for large entities and complex components.

The CKEditor 5 submodule demo, at last:

  • Add the Component button to your toolbar and enable the Embed components filter (<drupal-component> tag).
  • Choose which components editors may use; a modal opens the classic component form; edit/delete controls follow.
  • Block-level only for now — inline components are an open issue.
  • Demo lesson: render the form in the front theme, or your preview is in the wrong design system (more on that below).

The Views demo showed the three component layers: each row as a component, the style as a dynamic grid, and the new display plugin that makes the whole view output a component — exposed form in one slot, rows in another, no views-view.html.twig. This logic is shared with Display Builder: UI Patterns is its engine, so improvements flow both ways. For simple cases, UI Patterns alone is enough.

And a message to UI Patterns 1 users: 2.x adoption is almost entirely new sites. Time to migrate.

Rosetta — a path to core for our schema work

Dries' Rosetta initiative, announced at DrupalCon Rotterdam, is largely about JSON Schema. We've spoken it for years (SDC props, Icon API). Most Rosetta participants care about exporting Drupal to schema; UI Patterns excels at importing — resolving references, checking compatibility, wiring source plugins. So we can propose a JSON Schema manager and Typed Data improvements to core, and let UI Patterns shrink into a focused converter.

Design System API — several design systems on one page, no bleeding

Shibin Das presented a concept sitting on top of our core primitives: a Design System API that binds components, tokens, icon packs and styles together. The pain: an editorial page mixes several design systems — admin sidebar, contextual links, top bar, front theme — each with its own CSS, because core prescribes nothing.

The proposal, in short:

  • Skins and bindings on two axes — the site and the chrome (admin UI). In the demo, one binding switched the admin bar and contextual links to dark mode while the front theme stayed untouched.
  • Boundaries marked with data attributes; site builders decide which skin renders what.
  • Shared core tokens so contrib modules never hard-code colors, spacing or icons — a media library then looks right in any theme, with no shadow DOM.
  • Results: one style leak in ~500. Alpha, demo theme on GitHub (Drupal 11.5+/12), built in public.

The moment of the meeting: looking at the skin YAML, Pierre stopped him — "it's 90% like the Style API we're shipping in 12.1." The two will align.

Themes and community

  • A 2.1.0 release with two good breaking changes: the Canvas submodule now uses a proper validation schema.
  • DSFR follows upstream and adopted component suggestions. Daisy UI: Mikael joins Michael to push toward stable.
  • UI Suite is now an official organization on drupal.org. About 80 contributors a year deserve credit: add UI Suite under Work on your profile and credit the organization on your issues.

Q&A

Thomas Keitel asked whether the Views display extender keeps attributes like views AJAX IDs. Unknown — anything living only inside views-view.html.twig isn't rendered, since the goal is to replace legacy templates. Thomas will test. Rajab Natshah asked if this lands in core: via Rosetta for the low-level mechanisms, and via a proposed core plugin type for display-building tools. Moving Display Builder wholesale is unrealistic; moving pieces one by one, early next year, is the plan.
